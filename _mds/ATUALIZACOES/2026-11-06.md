## Decisões tomadas

- **Decisão:** testar a autenticação diretamente no Gmail, sem enviar e-mail.
- **Motivo:** o log da API registra apenas "Falha na entrega do e-mail de recuperação", sem o código SMTP. Por isso, timeout, bloqueio de rede e credencial inválida aparecem da mesma forma.
- **Alternativas:** disparar o fluxo "Esqueci minha senha", que envia um e-mail real e mostraria a mesma mensagem genérica no log.
- **Impacto:** foram feitas duas tentativas de autenticação com falha na conta Google. Nenhuma mensagem foi enviada.

- **Decisão:** manter o guia do SMTP dentro deste registro, não em arquivo próprio.
- **Motivo:** pedido do desenvolvedor, que não quer guias soltos em `_mds/`.
- **Impacto:** os registros de 15/10/2026 e 05/11/2026 foram preservados como histórico e ainda citam `_mds/SMTP.md`. A entrada `_mds/SMTP.md` do `.gitignore` foi mantida.

- **Decisão:** o script usa o banco padrão do `appsettings.json` quando nenhuma connection string for informada.
- **Motivo:** o banco `guide_test` da porta 55439 era de validação local e não existe em outro clone.
- **Alternativas:** manter 55439 como padrão, que quebra em qualquer outra máquina, ou criar um parâmetro só para o banco, o que duplicaria a variável de ambiente já aceita.
- **Impacto:** nesta máquina, o script passa a usar `localhost:5432/sicou-dev`. Para usar outro banco, defina `ConnectionStrings__DefaultConnection` antes de rodá-lo. A API aplica as migrations pendentes no banco escolhido.

- **Decisão:** separar a URL do frontend do Compose (`SICOU_FRONTEND_URL`) da URL do script local (`SMTP_FRONTEND_BASE_URL`).
- **Motivo:** o mesmo `.env.smtp.local` serve ao script (Vite, 5173) e ao Compose (3000). Com uma só variável, um dos dois sempre gerava link errado, e o guia mandava editar o arquivo antes de trocar de modo.
- **Alternativas:** manter a variável única e a edição manual, sujeita a esquecimento.
- **Impacto:** o Compose já fixa CORS em `localhost:3000` e a API em `localhost:8080`, então a mudança não reduz flexibilidade. Para publicar em outro endereço, defina `SICOU_FRONTEND_URL`.

## Configuração, banco e implantação

Não houve alteração de código, migration ou configuração versionada. A correção depende de uma nova senha de aplicativo em `.env.smtp.local`, que é local e não deve ser registrada.

### Guia do SMTP com Gmail

O fluxo **Esqueci minha senha** dispara automaticamente um e-mail ao endereço cadastrado de um usuário ativo. O link permite escolher uma nova senha, expira em 30 minutos e pode ser usado uma vez. Não é necessário agendamento.

**Configuração local.** O arquivo `.env.smtp.local`, ignorado pelo Git, contém a configuração do remetente (modelo em `.env.smtp.example`). `SMTP_PASSWORD` recebe uma senha de aplicativo da conta Google. Não use a senha comum nem registre o segredo em documentação. Para gerar a credencial, habilite a verificação em duas etapas e acesse [Senhas de aplicativo Google](https://myaccount.google.com/apppasswords). Veja a [orientação oficial](https://support.google.com/accounts/answer/185833?hl=pt-BR).

Valores: `smtp.gmail.com`, porta `587`, STARTTLS (`SMTP_ENABLE_SSL=true`). O mesmo endereço vai em `SMTP_USERNAME` e em `SMTP_FROM_ADDRESS`. Para o frontend local com Vite, use `SMTP_FRONTEND_BASE_URL=http://localhost:5173`.

**Iniciar a API local com SMTP.** Com o PostgreSQL local ativo, confira os campos:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\start-backend-smtp.ps1 -ValidateOnly
```

Encerre a API anterior que ocupa a porta 5175 e inicie em outro terminal:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\start-backend-smtp.ps1
```

O script carrega as variáveis SMTP apenas para o processo e restaura o ambiente ao encerrar. Usa o SDK em `.tools/dotnet` quando existir (pasta local, ignorada pelo Git); senão, o `dotnet` do PATH (.NET 8). O banco é o padrão do `appsettings.json` (`localhost:5432`, `sicou-dev`), a menos que `ConnectionStrings__DefaultConnection` já esteja definida. Ao iniciar, a API aplica as migrations pendentes nesse banco. A validação de campos não comprova autenticação nem entrega.

**Docker Compose.** Com Gmail:

```powershell
docker compose --env-file .env.smtp.local up -d --build
```

Sem `--env-file`, o envio vai para o Mailpit (`mail:1025`, caixa em `http://localhost:8025`), porque não há `.env` na raiz. O link do e-mail usa `SICOU_FRONTEND_URL` (padrão `http://localhost:3000`, porta do frontend do Compose), não o `SMTP_FRONTEND_BASE_URL` do script local. Assim, o mesmo `.env.smtp.local` serve aos dois. Depois de um `git pull` que altere backend ou frontend, use `--build`: sem ele, o Compose reaproveita as imagens antigas.

**Validar o disparo.** Na tela de login, clique em **Esqueci minha senha** e informe um e-mail real cadastrado. Confira recebimento e spam, abra o link e redefina a senha. Endereços `example.test` das contas de demonstração não recebem e-mail. O botão administrativo **Resetar senha** gera senha temporária na tela e é um fluxo separado.

A resposta pública não revela se o usuário existe. Falhas SMTP são registradas genericamente nos logs da API; HTTP de sucesso sozinho não comprova entrega. Links localhost funcionam somente no computador que executa o frontend.

**Erro `535 5.7.8 BadCredentials`.** Se o Gmail responder `535 5.7.8 Username and Password not accepted`, a rede e o TLS estão funcionando e o problema é a credencial. Causas comuns:

- a senha de aplicativo foi revogada ou substituída; trocar a senha da conta Google revoga todas as senhas de aplicativo;
- a verificação em duas etapas foi desativada (sem ela não há senha de aplicativo);
- `SMTP_USERNAME` não é a mesma conta que gerou a senha de aplicativo;
- foi usada a senha comum da conta em vez da senha de aplicativo.

Gere uma nova senha de aplicativo, cole em `SMTP_PASSWORD` (com ou sem espaços) e reinicie a API pelo script. Como a API não registra o código SMTP, teste a autenticação fora dela quando precisar identificar a causa.
